# Переход от ПР2 к ПР3

| ПР2 | ПР3 | Что сохранено |
|---|---|---|
| словарь спортсмена | Athlete(User) | имя, возраст, город, уровень |
| словарь вида спорта | SportType | название, инвентарь |
| словарь события | TrainingEvent | дата, место, вместимость, уровень |
| словарь заявки | MatchRequest | участник, событие, статус |
| available_slots(data, id) | event.available_slots | подсчёт свободных мест |
| cancel_request(data, id) | request.cancel() | история и освобождение места |
| join_event | сервис + методы объектов | дата, уровень, дубликаты, вместимость |
| JSON со ссылками по ID | тот же JSON, ссылки на объекты в памяти | совместимость файлов |

Проверка отсутствия регрессий: одни и те же 36 тестовых случаев меню,
бизнес-логики и хранения проходят на обоих этапах; новые 11 проверок покрывают
наследование, полиморфизм, инкапсуляцию, идентичность ссылок, копирование,
сериализацию и загрузку исторических заявок. Структура исходных данных ПР1
и точные строки трёх функций сохранены для допустимых входов.

Проверка JSON не заменяет проверки моделей: загрузчик защищает границу файла,
конструкторы и методы — создание объектов в коде. Старые активные заявки
восстанавливаются даже после даты тренировки, но новая запись запрещена.
