# SportPartner Finder — практическая работа 2

Система поиска спортивных партнёров для любительских тренировок.
Продолжение исходного проекта ПР1: https://github.com/MirBut23/SportPartner-Finder
Автор: Бутенко А.Д., ЭФБО-14-24.

## Запуск

Python 3.10 или новее. Программа использует только стандартную библиотеку.
Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python main.py
```

В Windows активируйте окружение командой `.venv\Scripts\activate`.
Чтобы демонстрационные данные оставались актуальными независимо от дня защиты:

```bash
python main.py --today 2026-09-22
python -m pytest -q
python -m flake8 .
```

Дата по умолчанию — реальная текущая дата. Параметр `--today` задаёт только
дату проверки учебного сценария. Прошедшие тренировки видны в каталоге,
но не допускают новую запись. Для отдельного файла: `--data путь/к/store.json`.
Перед демонстрацией скопируйте `data/store.json`: изменения меню сохраняются
сразу. Для восстановления можно вернуть эту копию.

## Возможности

1. Каталог тренировок и профилей, справочник видов спорта.
2. Поиск по городу, спорту, уровню спортсмена, дате и свободным местам.
   Уже посещаемые спортсменом события исключаются из поиска.
3. Сортировка по дате или вместимости без изменения исходного списка.
4. Запись с проверкой даты, уровня, дубликатов и свободных мест.
5. Отмена заявки с сохранением истории и освобождением места.
6. Добавление спортсменов и тренировок.
7. Статистика: активные/отменённые заявки, события, города, виды спорта.
8. Сохранение и восстановление JSON, сообщения об ошибках без аварии меню.

## Структура и преемственность ПР1

- `main.py` — запуск меню, без побочных действий при импорте.
- `sportpartner/cli.py` — цикл while, ввод и обработка ошибок.
- `sportpartner/service.py` — функции обработки списков и словарей.
- `sportpartner/utils.py` — три исходные функции ПР1 и проверки значений.
- `sportpartner/validation.py` — проверка структуры JSON и ссылок.
- `sportpartner/storage.py` — чтение/запись с with и атомарной заменой файла.
- `data/store.json` — спортсмены, виды спорта, тренировки, заявки.
- `tests/` — pytest: бизнес-правила, файлы и каждый пункт меню.
- `docs/pr1_original.py.txt` — неизменённый исходный сценарий ПР1.
- `docs/demo.txt` — фактический вывод контрольного сценария.

Данные представлены словарями и списками. Пользовательских классов в ПР2 нет.
`COLLECTIONS` — кортеж имён коллекций; статистика городов использует множество;
`find_events` — генератор; сортировка использует lambda; циклы обходят данные.
Функции снабжены docstring и аннотациями типов. Интроспекцию можно показать:
`help(sportpartner.service.join_event)` после импорта модуля.

## Данные и правила

Корневой объект JSON содержит четыре списка: `athletes`, `sports`, `events`,
`requests`. Все записи имеют положительный уникальный `id` внутри коллекции.
`events.sport_id`, `requests.athlete_id` и `requests.event_id` — внешние ссылки.
Дата имеет формат YYYY-MM-DD; уровни 1–5, разница не больше 1 для записи;
статусы заявки: active и cancelled. Город — фильтр поиска, а не запрет поездки.
Начальное событие ПР1 сохранено: теннис, корт «Спартак», 05.10.2026,
4 места, 3 участника; Алексей с уровнем 2 может занять последнее место.

При повреждённом или отсутствующем файле запуск завершается с понятным
сообщением и кодом 1, файл не перезаписывается. Новое состояние сначала
проверяется и записывается во временный файл в том же каталоге, затем
заменяет основной. Ошибка сохранения не меняет состояние меню.
Это однопользовательский консольный прототип; параллельная запись несколькими
процессами и полноценная авторизация не реализованы.

## Демонстрация и проверки

Запуск с `--today 2026-09-22`: команды 1 → 4 (спортсмен 1, тренировка 1) →
1 → 5 (заявка 4) → 7 → 0. Свободных мест: 1 → 0 → 1.
Тесты используют отдельные данные и временные файлы, не изменяя каталог.
Выполнены 36 проверок pytest; flake8 проверяет код без исключения правил.
Точка останова для самостоятельного показа отладки: проверка свободных мест
в `join_event`; наблюдайте athlete, event, data и возвращаемую заявку.
